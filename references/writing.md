# 卡兹克式公众号写作执行协议

本协议用于完整公众号文章的构思、写作与改稿。表达依据见[03-expression-dna.md](research/03-expression-dna.md)，事实从[知识库索引](../wiki/index.md)进入。学习的是由事实得出判断、用具体场景解释变化的方式；叙述者默认是实际署名的用户，卡兹克文章中的“我”“朋友”“我们团队”保留原归属。

## 1. 先把已有材料变成可以写的东西

收到主题、链接、记录或草稿后，先判断本次交付：新写完整文章、改现有稿、只做选题大纲，还是同时交付HTML。用户已经指定便照做；只给主题时默认完成中文公众号文章，字数服从材料，不将4000—8000字设为门槛。

在内部填一张简短素材卡，不把卡片默认塞进正文：

| 项目 | 要回答的问题 |
|---|---|
| 署名与视角 | 谁在说话？用户提供了哪些可用亲历？ |
| 读者 | 哪类人会因为这条信息改变理解或下一步行动？ |
| 文章中心 | 读完后最值得记住的一项判断是什么？ |
| 触发点 | 哪条新信息、异常现象、实际障碍或人物行动使此文值得写？ |
| 证据 | 官方资料、用户记录、外部案例、历史原文分别支持哪些话？ |
| 限制 | 什么尚未开放、未测、无法确认，什么只是推测？ |
| 交付 | 正文、标题、HTML及图位中哪些是用户所需？ |

已有足够信息便推进。缺的只是口吻、篇幅、标题数量等可逆偏好，按本文默认值完成；缺的是关键事实时，先检索或核验。仅当个人经历、未公开数据等必须由用户提供且决定全文真实性时，集中问一个必要问题，同时完成不依赖它的结构或研究。

## 2. 先研究，再形成自己的角度

先读wiki索引，按主题读取相关综合页和source摘要；需要用某个历史判断、经历或短引语时，再打开raw完整上下文。知识库中的2024年产品资料只解释当时的作者判断，不能直接作为今天的教程、价格或排行榜。

涉及当前公司、产品、人物、价格、版本、开放资格与平台规则，使用可用工具查当前官方资料。涉及测试结果，核对输入、版本、时间、样例范围及成功失败；没有亲测记录就引用可核对的演示与他人记录，清楚说明归属。查不到关键事实时删去依赖它的结论或明确限制，不以气势补证据。

按题材选择研究问题：

- **新产品/模型**：到底改变哪项任务？普通人现在能否用？演示、有限邀测与已全量功能有何区别？失败或代价是什么？同一任务此前怎么做？
- **产品体验**：用户原来要做哪几个动作？新设计减少哪步阻力？谁能受益、谁未必需要？底层机制是官方确认还是根据行为推测？
- **人物/案例**：行动在什么时点发生？人物公开说过什么？具体困难、投入和结果有什么记录？哪些心理解释只属于作者推断？
- **行业批评**：被批评的事实是什么？样本能支持多大的判断？有没有更好的对照？动机、法律定性及整体因果是否越出证据？
- **项目复盘**：目标和约束是什么？什么真的试过？哪次决定改变结果？代价、失误与未解决问题是什么？工具步骤中哪些仍适用于今天？

不要把检索到的十条更新逐条抄进正文。形成一个足够具体的中心判断，例如“这个入口减少了读者查陌生概念时的跨页面操作”，再保留真正支持、限制或挑战它的材料。

### 从人物模型走到角度的正向示例

用[S043](../raw/articles/S043.md)已有历史材料做一次选择：文中记载手动同步文章的维护中断，以及自动同步上线后的重新推荐。M2本可追问问答准确率，但没有同条件测试，不能编一组效果对比；M1/M4则能解释有记录的维护动作和微信入口。由此选定的角度是“第一次能建库之外，第二个月是否还愿意继续用”。这是分析者归纳，不是作者原话或对新产品的结论。

**原创演示，转述历史材料，无新增实测：**

> 2024年那篇数字分身文章里，有个比文件容量更值得看的细节。卡兹克曾经把文章手动同步进知识库，后来停了。再推荐它时，打动他的变化是能自动同步新文章。
>
> 建好一个库，是某一天的事。让它一直有用，后面每一天都还要有人维护。这个动作足够麻烦，再漂亮的第一次体验，也未必能留下来。

正文先抓住一个不起眼的行为，再解释维护成本和持续使用的关系。新题目只有在新材料也支持时才走这条判断路径，不能把“自动同步”硬套成所有知识库稿的答案。

## 3. 选一条适合材料的推进路线

以下是可调的路线，允许混合，不能为了齐步骤虚构事实。

| 材料形态 | 推进路线 | 参考 |
|---|---|---|
| 模型发布与有据体验 | 触发事件 → 先前障碍 → 最值得看的结果 → 分维度案例 → 失败与使用条件 → 对创作者的具体意义 | [S025](../raw/articles/S025.md)、[S024](../raw/articles/S024.md) |
| 小功能与大体验 | 一个原有任务 → 新动作 → 结果 → 机制解释 → 另一个场景检验 → 设计判断 | [S026](../raw/articles/S026.md)、[S028](../raw/articles/S028.md) |
| 人物故事 | 令人想追问的结果 → 回到人物与困难 → 时间线上的行动 → 工具填补缺口 → 一个细节回收全文 | [S019](../raw/articles/S019.md) |
| 有证据的批评 | 具体对象与证据 → 为什么有问题 → 对照或机制 → 涉及谁的利益 → 可行判断或提醒 | [S017](../raw/articles/S017.md)、[S030](../raw/articles/S030.md) |
| 长流程复盘 | 成品与任务 → 关键限制 → 按阶段写卡点和取舍 → 结果与遗憾 → 协作及可迁移经验 | [S031](../raw/articles/S031.md)、[S032](../raw/articles/S032.md) |
| 新奇商业观察 | 一个能看懂的商品/行为 → 账怎么算 → 怎样交付 → 消费者为何愿意 → 风险和边界 | [S018](../raw/articles/S018.md)、[S027](../raw/articles/S027.md) |

每一大段都应推进一个问题。例如“为什么值得注意”之后，读者通常要问“到底如何做到”“结果哪里好”“哪里仍不行”“跟我有什么关系”。据此安排顺序，不固定开头必须故事、第二段必须反转、最后必须升华。

## 4. 先写事实和动作，再写情绪

先完成一版能连贯阅读的正文。首屏尽早让读者知道对象与看点；无需大段“随着AI发展”。产品先写输入、操作和结果，再解释术语；人物先有行动与时间，再有评价；复盘先有约束和选择，再有热爱。

每个主要评价按以下顺序检查：

1. **结果**：具体出现了什么？例如“第三个动作里，手中的杯子没有消失”，比“稳定性逆天”提供更多信息。
2. **比较**：为什么这个变化值得在意？以前哪里卡住，比较条件是否相近？
3. **范围**：是单个case、有限测试还是官方宣称？是否还有失败？
4. **影响**：哪类任务因此少一步、可多做什么，或者仍不能放心用？

这四项是判断支架，不要求每段四句。材料无法回答时，不必硬填。

情绪需要对象。兴奋要让人知道越过了哪道障碍，愤怒要指向哪项具体行为，感动要来自人物付出的时间与行动。句子里的“离谱、真的、我服了、破防”等不设配额；删去后意思毫无损失的口癖通常也可删去。粗口不是风格认证，可以按实际署名者平常表达选择。

## 5. 写得像一个人正在带读者看材料

使用自然的中文口语，保留具体名词、动作和合理的长解释。关键结果、转折、犹豫或情绪可以短段独立落下。不要把每个逗号变成换行，也不要所有段落都用三句话。

转场的任务是接续读者疑问：

- “这演示很漂亮，实际用起来要付出什么代价？”承接能力到成本。
- “但他真正想保存的，是照片里这个人的声音。”承接工具到人物愿望。
- “问题出在下一步。”只有后面能立刻指出具体问题时才有用。

上面三句为**原创演示**，不是卡兹克原话。新稿应从自己的材料长出转场，避免逐字循环。

允许冒号、引号、破折号、列表与分节。流程复盘、多个并列能力、操作步骤需要清楚结构时就使用；纯叙事可少标题。不要为消除“AI味”删掉正常标点或把完整论证改成口号。[表达DNA反例表](research/03-expression-dna.md#9-对旧skill假设的校正)给出原文依据。

引用和比喻应让理解更容易。一个恰当比喻可贯穿全文，但每次回收要增加一层理解；电影、文学或游戏知识只在确实解释动作、情绪、人物选择时出现。查不到准确引语就改为不带引号的概述，或不用。

## 6. 选择正文已经准备好的结尾

先用一句具体的话写清全文结果，再决定停在何处：适用人群和限制、下一步真实期待、开头动作的回钩、人物持续的愿望、项目中的选择与贡献者。文章已经建立价值冲突时，可再说它对普通人意味着什么。

没有铺垫的文化典故、生命哲学、文明进程不作默认尾声。“热爱”“光”“时代”也不作为自动收尾词。不要复制卡兹克账号的邮箱、署名、星标尾注和个人经历。用户想保留互动引导时，用其自己的账号与真实信息，简短自然。

## 7. 标题在正文之后定稿

内部生成几个方向，最终默认交付一个推荐标题；只有用户要候选时才增加。可选择“对象与动作”“体验后判断”“一项反常识关系”“项目结果与过程回报”。数字必须有相应记录，第一人称必须符合署名者身份。

对每个标题做承诺核对：读者因它期待什么？正文真的回答了吗？金额是流水、收入还是利润？“已上线”意味着哪些人能用？“取代、最强、唯一、首次”有无足够证据？问号不能洗掉正文对错误事实的暗示。

标题可以有情绪，但不能比关键证据更确定。单个官方样例可写“这个连续动作演示，让我开始期待AI表演”，不能凭它写“实测十小时，演员已经失业”。前句中“期待”仅代表署名者当下判断，仍要在正文说明来源是演示。

## 8. 常见失败与改写

以下全部是**原创演示，产品“青帆”及场景均为教学虚构**，不代表真实产品能力、实测记录或卡兹克原话。生成正式文章时只能替换为已核实的材料，不能将演示当案例。

### 失败A：只有亢奋，没有事情

失败稿：

> 太离谱了，真的。青帆这次直接杀疯了。一个全新的时代，来了。

改写：

> 青帆公布的演示里，一个人端起杯子，喝了一口，再把杯子放回桌面。最值得看的是最后一步：杯子回到了原来的位置，手指也没有跟着变成另一件东西。
>
> 如果后续开放版本能稳定做到这一点，想拍完整动作的人，就多了一种选择。现在能确认的，还只有这段演示。

改动依据：用具体结果解释看点，保留演示与稳定能力的距离；参考S025的成功/失败边界，而不是复制赞美词。

### 失败B：为制造现场感盗用经历

失败稿：

> 昨晚我收到内测，连续肝了十小时，跑了100多个case，激动得没睡。

若当前只有公开资料，改写：

> 官方这次给出的材料里，最想让我追问的是动作连续性。演示已经展示了一次成功；实际生成时要重试多少次、复杂背景下还稳不稳，材料没有回答。

若用户确实提供测试记录，则写其真实输入、结果和次数。不要用卡兹克的邀测、购买、同事或熬夜经历补足用户的空白。

### 失败C：把产品写成功能清单

失败稿：

> 青帆支持网页总结、划词翻译、智能问答、历史管理，是一站式高效AI平台。

改写：

> 读一篇陌生领域的文章，最打断人的往往是一个词。原来的做法是复制它，打开另一个页面，再把问题问一遍。
>
> 这次的入口放在选中文字后。按演示所示，解释留在原页面，读到哪儿就问到哪儿。它减少的是这一次离开文章的动作。

改动依据：先写任务阻力，再写设计意义；参考S026、S028。不额外编造节省百分比。

### 失败D：用文化词语替代结论

失败稿：

> AI的星河终将照亮每一个普通人。热爱可抵岁月漫长。我们，终将抵达彼岸。

改写：

> 对偶尔查一个陌生词的人，这个入口已经足够轻。至于要连续读几十页资料的人，引用是否完整、长文能否读全，仍是更值得继续验证的问题。

改动依据：回到本文讨论的读者与边界。无需每篇文化升华，S026本就可以停在体验判断。

### 失败E：把“有门槛”写成普遍劝退

失败稿：

> AI没有门槛，学会打字，人人都能做出电影级短片。

改写：

> 输入一句话不难，完成一个故事是另一组工作。角色能否接得上、镜头为什么这样排、失败画面怎么修，都要有人作决定。工具把一部分操作变轻了，作品的判断还得继续练。

改动依据：同时容纳S017工具使用门槛与S031/S032作品创作门槛的不同层级，不能挑一句话消灭内部张力。

## 9. 完稿检查与默认交付

通读正文，只修会影响真实性、理解和完整性的地方：

- “我、我们、朋友、团队”是否都有正确主人？引用的卡兹克经历是否被误写为用户经历？
- 核心事实是否可追溯？版本、日期、价格与权限是否核过？任何当前结论是否错误地依赖旧库？
- 每项大判断是否有结果或理由？样本、演示和预测有没有被写成普遍事实？
- 中段是否回答了“为什么、怎么做、哪里不行、跟谁有关”？删去重复赞美后有无信息损失？
- 结尾是否回收正文？标题的强承诺是否已兑现？有没有为了像作者而添加虚构亲测、粗口或典故？
- 若保留图位，每张图承担何种证据或解释作用？没有看过图片时不描述其中细节。没有媒体文件时不能声称已嵌入真实配图。

完整文章的默认交付遵循[主SKILL第6步](../SKILL.md)：1个推荐标题、Markdown正文、按参考样式渲染的HTML片段及预览、来源说明。只改稿、只提纲或只要纯文字时按用户范围交付。不把素材卡、内部打分、改稿过程插进文章；待核实事项和引用来源放文章外，不伪装成作者口吻。事实来源应可追溯，但不因风格而省略必要归属。

一次任务完成后，如果产生了有价值的新资料或跨文对照，按知识库schema更新wiki与日志；原始raw保持不改。不要为了这次文章顺口而修改历史原文的观点、日期或矛盾。
